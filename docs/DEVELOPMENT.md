# Сборка и проверки

## Windows

Нужны .NET 8 SDK, PowerShell 7 и Git. Из корня репозитория:

```powershell
pwsh -NoProfile -File scripts/build.ps1 -Task Build
pwsh -NoProfile -File scripts/build.ps1 -Task Test
pwsh -NoProfile -File scripts/build.ps1 -Task Publish
```

`Test` проверяет синтаксис скриптов, собирает приложение, запускает автономные
проверки движка и отдельный STA/WPF-процесс с настоящими контролами.
`Publish` создаёт автономный Windows x64 пакет, проверяет его состав и версию,
запускает опубликованный EXE с изолированным профилем и проверяет установку
локального пакета следующей версии с настоящим перезапуском. Отдельный сценарий
прерывает установку и проверяет восстановление при следующем запуске.
Версия для этого сценария собирается только как локальная фикстура CI;
её тег и GitHub Release не создаются. Затем собирается ZIP с SHA-256.

Результаты находятся в `dist`. Упаковка выполняется только в каталогах проекта.

## Проверки движка на другой ОС

```bash
dotnet run --project tests/TextDownloader.Core.Tests -c Release
```

Эти тесты используют искусственный HTML и подменённый HTTP-источник.
Они не обращаются к Sefan или Bestweapon и не требуют личных данных.
Проверяются интервалы и отмена ожидания, возобновление с 21-й страницы
после сохранения первых 20, ручная замена адреса, состав циклов,
полнота глав и оглавления EPUB/FB2.

Для сетевой проверки открытых ранобэ и фанфиков запустите отдельный сценарий.

```bash
dotnet run --project tests/TextDownloader.Core.Tests -c Release -- --live-public-sites
```

Для каждого зарегистрированного сайта сценарий случайно выбирает произведение
из открытого каталога, скачивает первую главу через обычный предпросмотр
и сверяет её текст после экспорта в FB2. Можно указать несколько доменов
после `--live-public-sites` для проверки только выбранных сайтов.
Сценарий работает без учётных данных и требует доступ к сайтам из интернета.
В PR с новой группой источников GitHub Actions запускает этот сценарий
и проверяет десять сайтов этой группы. Параметр `--batch` принимает номер группы. Ручной запуск
**Public fiction site checks** проверяет все подключённые открытые сайты.

На Linux можно отдельно проверить компиляцию WPF.

```bash
dotnet build tests/TextDownloader.UiTests -c Release -p:EnableWindowsTargeting=true
```

Сценарии с WPF-контролами и опубликованным EXE выполняются в Windows.
Их запускает workflow **Windows build and release** в PR.

## Ветки после слияния

GitHub Actions сохраняет результат каждого слияния в `main` в ветке
`merge-snapshots/<полный SHA>`. При слиянии через squash или rebase
используется итоговый коммит, который GitHub указывает для PR.
Ветка остаётся доступной после удаления рабочей ветки. Повторный запуск
проверяет существующий указатель.

## Версия и выпуск

Каждое слияние в `main` запускает workflow **Release main merges**. Он собирает
и проверяет конкретный коммит в Windows, создаёт тег и публикует установочный
архив. Обычные merge-коммиты обнаруживаются в истории `main`, squash и rebase
подхватываются по событию закрытого PR. В одном push может быть несколько
слияний. Каждый получает свой выпуск.

`Version.props` задаёт базовые версию и коммит. Номер патча выпуска равен
базовому номеру плюс число коммитов по первому родителю между базой и
слиянием. Повторный запуск получает тот же тег. Прямые коммиты и промежуточные
коммиты rebase могут оставлять пропуски в номерах. Ручная отправка тега для
штатного выпуска не нужна. При сбое перезапустите исходный workflow.

В выпуск входят `TextDownloader-Windows-x64.zip` и `SHA256SUMS.txt`.
Сценарий выпуска проверяет принадлежность и состав черновика и не заменяет
ранее опубликованные чужие файлы. В release job есть право записи в GitHub;
обычная сборка использует только чтение.

## Подключение источника

Добавьте папку адаптера в `src/TextDownloader.Core/Sources/`. Реализуйте
`IStorySource` для проверки адреса, получения первой страницы и разбора
страниц. Общий загрузчик проверяет порядок, применяет кеш и отдаёт
`BookDocument`. Если у источника собственное оглавление или набор отдельных
публикаций, адаптер может реализовать `IBookStorySource` и вернуть книгу с
главами. Для цикла с независимыми цепочками страниц можно переиспользовать
загрузчик страниц через `IPagedBookSource`.

Добавьте фабрику в `SupportedStorySource.CreateLoggedFactory`. Она получает
интервал запросов, журнал и ограничитель запросов источника. Адаптер
определяет правила адресов, допустимые перенаправления, адрес для
возобновления, отображаемое имя и единицу прогресса. Экран очереди,
форматы книги и правила хранения кеша работают через эти контракты.
Для проверки используйте синтетические ответы в тестах движка.

## Контракты

- URL одного рассказа ограничены адаптером; внешние ссылки не обходятся.
- Подтверждение возраста отправляется только после явного выбора пользователя.
- Кеш хранит заменяемые страницы и проверяется по контрольной сумме.
  Перед началом новой загрузки без кеша очередь сохраняет идентификатор
  отдельной попытки. После сбоя она восстанавливает эту попытку.
- В кеше старой версии у первой страницы Sefan может отсутствовать
  результат разбора оглавления. При первом использовании такого кеша
  программа заново запрашивает эту страницу для обнаружения частей,
  затем проверяет остальные сохранённые страницы.
- Штатная загрузка Sefan принимает страницы чтения. Адрес оглавления
  проверяется и запрашивается только при обходе выбранного рассказа.
- Успех требует доказанной полноты, корректного EPUB/FB2 и публикации файлов.
- Тяжёлые операции выполняются асинхронно; отмена не удаляет чужие файлы.
- Личные тексты, профили, ключи, `bin`, `obj` и `dist` не коммитятся.
